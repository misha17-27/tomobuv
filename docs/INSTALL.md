# Установка и переезд со старого сайта (Webasyst) на новый

Требования хостинга: **PHP 8.1+** (рекомендуется 8.3; расширения pdo_mysql, mbstring, gd, openssl, curl, zip, xmlreader,
dom, simplexml; желательно intl, exif), **MySQL 5.7 / 8.0 или MariaDB 10.3+**, Apache (или LiteSpeed) с mod_rewrite
(обычный cPanel/ISPmanager подходит), cron, доступ по SSH (или разовые задания cron — см. ниже).
Установка «с нуля» по этой инструкции проверена на MariaDB 10.3, MySQL 5.7 и MySQL 8.0 (строгий режим sql_mode по умолчанию), PHP 8.1 и 8.3.

`curl` — для загрузки прайсов и фото по ссылке и WhatsApp-уведомлений (без него работает, но фото грузятся по одному); `zip`, `xmlreader`, `dom`, `simplexml` —
для импорта XLSX/XML/YML. Что подключено на хостинге — видно в админке: «Состояние системы».

**PHP в командной строке** должен быть той же версии, что и у сайта: `php -v` (на cPanel часто нужен полный путь,
например `/opt/cpanel/ea-php83/root/usr/bin/php`, на ISPmanager — `/opt/php83/bin/php`). Этот же путь — в заданиях cron.

## 1. Подготовка (старый сайт продолжает работать)

1. Создайте на хостинге **две базы**: `tomobuv` (новая) и `tomobuv_old` (копия старой, нужна только для переноса).
2. Загрузите свежий дамп старой базы в `tomobuv_old` (phpMyAdmin → Импорт или `mysql tomobuv_old < tomobuv_db.sql`).
3. Залейте код (из GitHub) в папку, например `/home/USER/tomobuv/`.
   - Лучший вариант: корень домена (DocumentRoot) → папка `public/`.
   - Если панель не даёт сменить корень — положите проект целиком в `public_html`: корневой `.htaccess`
     сам направит запросы в `public/` и закроет служебные папки.
4. Скопируйте `config/config.example.php` → `config/config.php` и заполните: `base_url` (`https://tomobuv.com.ua`,
   на время проверки — временный адрес), доступы к обеим базам, `app_key` (случайная строка 64 символа:
   `php -r "echo bin2hex(random_bytes(32));"`), почту (`mail.admin_to`; SMTP можно и позже в админке, см. ниже).
   `debug` — **false**, `images.remote_base` — **пусто** (фото берутся из `public/wa-data/`, см. ниже).
5. Права на запись: `storage/` (и вложенные), `public/uploads/` и `public/wa-data/` — 775 (миниатюры фото создаются
   в `public/wa-data/public/shop/products/`). `config/config.php` после заполнения — 640 (только чтение для остальных).
   `bin/install.php` сам создаёт папки в `storage/` и предупреждает, если записи нет.
6. Лимиты PHP: в проекте есть `public/.user.ini` — `upload_max_filesize = 16M`, `post_max_size = 32M`,
   `memory_limit = 256M`, `max_execution_time = 120` (прайсы и фото из админки, импорт). На PHP-FPM/FastCGI
   (обычно на cPanel/ISPmanager) хостинг подхватит его сам в течение 5 минут; если PHP работает модулем Apache —
   выставьте те же значения в панели («Настройки PHP» / «Select PHP Version → Options»).
   Проверка: админка → «Состояние системы» → «Размер загрузки».

## 2. Перенос данных

Из папки проекта (`cd /home/USER/tomobuv`), строго по порядку — каждая команда должна закончиться без ошибок:

```bash
php bin/install.php            # создать таблицы новой базы (≈2–6 с)
php bin/import-webasyst.php    # перенести всё (≈1–2 минуты на 107 тыс. товаров; на MySQL 8 — дольше, чем на MariaDB)
php bin/i18n-seed-uk.php       # украинская версия: переводы из database/i18n/uk/ → база (≈20–40 с)
php bin/create-admin.php you@mail.com НовыйПароль admin   # свой вход в админку (пароль от 10 символов)
php bin/seo-autofix.php --dry-run   # проверка SEO: должно быть «изменений 0» (перенос и сид уже привели title/description к норме)
```
- SEO title/description приводятся к норме (title 30–70, description 70–170 символов) **автоматически в конце** `import-webasyst.php`
  и `i18n-seed-uk.php`: «машинные» мета старого сайта («= название», «купить … в Одессе») очищаются — работают стандартные шаблоны,
  свои тексты вне нормы дополняются или сокращаются (строка «SEO title/description приведены к норме: изменено N (пакет №…)»).
  Каждый запуск — пакет в журнале: `php bin/seo-autofix.php --list`, откат — `php bin/seo-autofix.php --revert=N`
  (или админка → «SEO» → «Исправить автоматически» → «Пакеты»). Повторный запуск ничего не меняет. Подробнее — docs/ARCHITECTURE.md, «SEO».
- Товары, заведённые на старом сайте одним кодом («60189A»), перенос сам называет «Категория Бренд Код» — «Зимняя обувь Tom.m 60189A»
  (строка «Названия-коды дополнены…» после шага products; адреса страниц не меняются, пустой артикул получает код), украинское
  название им ставит `i18n-seed-uk.php`. Отдельно, для уже перенесённой базы: `php bin/product-names.php --dry-run` — показать
  «было → стало», `php bin/product-names.php` — применить (повторный запуск ничего не меняет). Подробнее — docs/ARCHITECTURE.md, «Автоназвание товара».
- `install.php` можно запускать повторно (и нужно — после обновления кода: добавит новые таблицы/колонки/индексы).
  Строка «часть ждёт следующих миграций — повтор в конце» — норма: такие файлы выполняются ещё раз после остальных.
  Если в конце «Ошибок: N» — дальше не идите, пришлите вывод разработчику.
- Нет SSH — добавьте в панели разовое задание cron на ближайшую минуту с той же командой и выводом в файл,
  например `cd /home/USER/tomobuv && php bin/install.php > storage/install.txt 2>&1`, дождитесь, прочитайте файл,
  удалите задание; затем так же остальные команды по одной.

Сотрудники старой админки Webasyst входят в новую (`/admin/`) со своим прежним e-mail/логином/телефоном и паролем
(все — с полными правами). Сразу после переноса откройте «Сотрудники» и отключите лишних или сделайте их менеджерами.
Клиенты входят в кабинет со старыми паролями (при первом входе пароль перешифровывается).

**Фото товаров**: скопируйте со старого сервера папки
`wa-data/public/shop/products/`, `wa-data/protected/shop/products/`, `wa-data/public/shop/brands/`,
`wa-data/public/shop/wmimageincatPlugin/`, `wa-data/public/shop/themes/balance/img/`, `wa-data/public/site/`, `wa-data/public/blog/`
в `public/wa-data/` нового сайта (адреса картинок сохраняются 1-в-1 — позиции в Google Картинках не теряются).
Проще всего — архивом через SSH/файловый менеджер: `tar czf wa-data.tgz wa-data` на старом сервере.
После распаковки удалите из `public/wa-data/` служебные файлы Webasyst — `.htaccess` (кроме `wa-data/protected/.htaccess`)
и `*.php` (например, `wa-data/public/shop/products/thumb.php`): `find public/wa-data -name '*.php' -delete` и
`find public/wa-data/public -name .htaccess -delete`. Иначе старый `.htaccess` перехватит создание миниатюр
(PHP в `wa-data/` всё равно не исполняется — `public/.htaccess` запрещает, но миниатюры не создадутся).

## 3. Cron

```
0 * * * *  php /home/USER/tomobuv/bin/cron.php >/dev/null 2>&1   # очистка кэша, корзин, сессий; публикация отложенных статей; автозагрузка поставщиков (раз в час)
```
Вместо `php` — полный путь к PHP нужной версии (см. «PHP в командной строке» выше). Что cron работает — видно
в «Состоянии системы» (строка «Cron»). Этот же cron раз в час решает, пора ли запускать автозагрузку поставщиков
(Jong•Golf, «Хит обуви», Tom.m — у каждого своё расписание, см. разделы ниже), и продолжает прерванные запуски.

Автоимпорт прайса поставщика по расписанию (необязательно): в админке «Импорт / экспорт» сохраните настройки
как профиль со ссылкой на файл поставщика и добавьте задание, например каждую ночь в 3:30:
```
30 3 * * *  php /home/USER/tomobuv/bin/import.php ID_профиля >> /home/USER/tomobuv/storage/logs/import-cron.log 2>&1
```

Ночная перестройка индекса каталога (необязательно, но рекомендуется): после каждой правки товара индекс и счётчики
фильтров обновляются точечно; если один товар одновременно правят из админки и импорт, счётчики фильтров могут
разойтись на единицу-другую — ночная полная перестройка их выравнивает:
```
0 4 * * *  php /home/USER/tomobuv/bin/reindex.php >> /home/USER/tomobuv/storage/logs/reindex-cron.log 2>&1
```
Длительность на полной базе (107 тыс. товаров, 113 категорий, 243 тыс. строк индекса, 843 тыс. значений характеристик):
~4,4 с (замер на копии базы, MariaDB 10.3); на слабом хостинге — дольше. Перестройка идёт одной транзакцией: пока она
не закончилась, витрина показывает прежний полный индекс, потом сразу новый — запускать можно в любое время.
Сохранения товаров в админке и пачки импорта в это время не теряются: товар записывается сразу, а его строки индекса —
после перестройки (блокировка записи индекса, GET_LOCK MySQL). Перестройки идут по одной (блокировка
`storage/cache/reindex.lock` — общая для `bin/reindex.php`, кнопки «Перестроить индекс каталога» и «Завершения» импорта;
второй запуск ждёт первый до 10 минут); импорт на это время показывает «Идёт перестройка индекса каталога» и продолжает сам,
шаг импорта, попавший на взаимную блокировку InnoDB, повторяется без сообщения об ошибке (запись в `storage/logs/app-*.log`).
Прав CREATE/DROP/LOCK TABLES перестройка не требует — только SELECT/INSERT/UPDATE/DELETE. С binlog в формате STATEMENT
(редкость: MySQL 5.7+ по умолчанию ROW, MariaDB — MIXED) она идёт в REPEATABLE READ и дольше держит строки товаров.

## Почта и WhatsApp

- **Почта** (письма покупателю о заказе, уведомления о заказах и заявках): админка → «Почта (SMTP)» — адрес для
  уведомлений, отправитель и SMTP (например, Gmail: `smtp.gmail.com`, порт 465, SSL, логин — адрес, пароль —
  «пароль приложения» Google), кнопка «Отправить тестовое письмо». Без SMTP письма идут через `mail()` хостинга
  и часто попадают в спам. То же можно задать в `config/config.php` (`mail.*`) — значения из админки главнее.
  Ошибки отправки не мешают оформлению заказа и пишутся в `storage/logs/`.
- **WhatsApp** (новые заказы, «купить в 1 клик», по желанию — заявки): админка → «Настройки → WhatsApp» —
  номера получателей и сервис: Green-API (ваш WhatsApp по QR-коду: idInstance, apiTokenInstance) или WhatsApp Cloud API
  от Meta (Phone number ID, токен, при необходимости шаблон). Кнопка «Отправить тестовое сообщение», журнал отправок — там же.
  Хостинг должен разрешать исходящие HTTPS-запросы (на shared-хостинге обычно разрешены).

## Автозагрузка Jong•Golf (официальный сайт бренда jonggolf.com; запасной путь — API)

«Каталог → Поставщики → Jong•Golf» (только администратор). Магазин — дилер бренда: данные и фото с сайта бренда брать можно.
Источник — настройка «Откуда загружать»: **сайт бренда** (по умолчанию) или API поставщика (пускает только IP из белого списка и давно
не обновлялся — запасной путь, раздел ниже). Связи с товарами (по коду цвета «B40678-3»), категории и «Обзор» у источников общие —
переключать можно без перепривязки. По умолчанию **выключена**.

С сайта бренда загрузчик читает **весь каталог в наличии одним запросом** (`/ru/catalog/?limit=1000`, ≈2,2 МБ, по сети ≈110 КБ, ≈2 с):
код цвета, раздел, пол, ряд, пар в ящике, цена пары и ящика, старая цена, фото. Карточка модели (материалы, повторные размеры, описание,
доп. фото) и фото — только для новых цветов. Бережно — как у Tom.m: один поток, пауза ≥ 1,5 с (по умолчанию 2), User-Agent
`TomobuvLoader/1.0 (+https://tomobuv.com.ua)`, robots.txt обоих хостов (www.jonggolf.com и public.jonggolf.com — фото), 429/5xx — пауза
с удвоением, 403 / проверка браузера / блок-страница фильтра — остановка «нужна проверка». К API (`/api/json/…`) этот путь не обращается.

**Фото — нужно разрешение бренда.** Фото товаров лежат на `public.jonggolf.com/files/products/…`, а robots.txt этого хоста (такой же,
как у www) содержит `Disallow: */product*` — это закрывает и `/files/products/`. Загрузчик такие фото **не запрашивает**: новый цвет без фото
не создаётся (или создаётся без фото — настройка «Добавлять без фото»), в отчёте и на «Обзоре» — предупреждение. Попросите бренд добавить
в robots.txt `public.jonggolf.com`, например:
```
User-agent: TomobuvLoader
Allow: /files/products/
```
(или `Allow: /files/products/` в группе `User-agent: *`) — загрузчик подхватит это сам (robots.txt перечитывается раз в сутки), товарам без фото
фото добавится следующим проходом. На 20.10.2026 закрыто: из 729 цветов в наличии новых для нас 329 — все ждут фото.

**Как включить (сайт бренда):**
1. `php bin/install.php` (таблицы `supplier_*` — общие с другими поставщиками). Разделы бренда («Категории») заполняются черновиком сами
   при первом открытии (`php bin/supplier-jonggolf.php --seed-map`): 20 разделов «сезон | категория» → «ДЕТСКАЯ ОБУВЬ > …», по рядам —
   12-26 / 26-32 / 32-38 по нижнему размеру ряда. Сначала ищется строка таблицы сочетаний старого загрузчика (по русским названиям
   сайта, затем по украинским, как в API), разделы — запасное правило.
2. **Наценка** — «Настройки» → «Наценка» (цены бренда — закупочные: без коэффициента загрузку с сайта нельзя ни включить, ни запустить).
   Решение владельца (октябрь 2026) — ×1: в локальных настройках `jonggolf.markup_k = 1` (в коде по умолчанию не задана).
3. «Обзор» → «Проверить связь» (robots.txt и первая страница каталога, 1–3 запроса), затем «Пробный прогон» «С сайта бренда» (1 запрос,
   ничего не пишет в каталог): найденные товары, цены до и после наценки, что станет «нет в наличии», что добавится. На 20.10.2026:
   у бренда 729 цветов (321 модель), найдено 400 наших (385 по связи, 15 заведённых вручную), новых 329 (все ждут фото), станут «нет в наличии» 179
   (после второго полного прохода — скрыты), цена изменится у 135 (134 дешевле: скидки бренда), закупочная — у всех 400.
4. «Настройки» → «Автозагрузка по расписанию включена» → «Сохранить». Первый запуск можно сразу — «Запустить сейчас».

**Что делает запуск:** найденные — цена пары цвета (× наценка), старая цена (скидка бренда), закупочная, ящик, ряд, наличие; скрытый
загрузчиком и снова появившийся — показывается; категория — по таблице («Менять категорию», включено), заведённые вручную берутся
под загрузчик (название, адрес, SEO не меняются). Цвета нет в списке (бренд не показывает цвета без остатка) — у нас сразу «нет в наличии»,
после 2 полных проходов подряд — скрыт (остановленный, неполный, по сохранённым страницам — ничего не меняет; больше половины активных —
отмена). Новые — только в наличии, с ценой, категорией, рядом и фото: «Зимняя обувь Jong•Golf B40678-3» / «Зимове взуття …» (RU и UA),
артикул — код цвета, характеристики по-русски из списка и карточки (существующие значения), описание, фото → холст 700×700, SEO — шаблоны
сайта; не больше 500 за запуск. «Хит обуви» товары Jong•Golf не загружает (бренд в пропускаемых во всех написаниях).
Значения характеристик с сайта бренда — по-русски (у товаров из API были украинские в RU-колонке — «Для дівчаток»; «Перезаписывать
характеристики» переведёт найденные на русские). Для /ua/ перевод значения — `database/i18n/uk/feature_values.php` и
`php bin/i18n-seed-uk.php features` (заполняет только пустые): пол Jong•Golf там уже есть, новые материалы из карточек — дописать туда.

**Загрузка с нуля** (каталог собирается заново): ≈730 цветов в наличии, на новый цвет — 1–2 фото, на модель — карточка (≈2,5 запроса
на цвет); запуск берёт не больше 500 новых и 1 500 запросов — весь бренд за 2 запуска (cron ведёт кусками по 40 мин). **Пока бренд
не разрешил фото**, с нуля без «Добавлять без фото» не создастся ничего; с ней — за 2 запуска без фото (только карточки, ≈320 запросов).

**Расписание** (решение владельца): полная сверка цен и наличия всех товаров **каждые 5 ч круглые сутки** (окно 0–23, период 5 ч;
у Jong•Golf каждый проход полный — быстрого нет). Запросов к jonggolf.com в сутки: ≈4,8 прохода × **1** + robots.txt двух хостов = **≈7**
(+ карточка модели и 1–2 фото на каждый новый цвет). Проход — 2–5 с. Отдельная строка cron не нужна (хватает `bin/cron.php`), если хочется:
```
40 * * * *  php /home/USER/tomobuv/bin/supplier-jonggolf.php >> /home/USER/tomobuv/storage/logs/jonggolf-cron.log 2>&1
```
Склад и страну сайт бренда определяет по IP (cookie `view_data`): с украинского IP хостинга наличие и цены могут отличаться от снятых
при разработке — проверьте первым пробным прогоном на сервере.

Командная строка (`bin/supplier-jonggolf.php`): без параметров — как cron; `--test`; `--now [--limit=N] [--aids=B40678-3,…]` (источник —
из настроек); `--dry-run [--source=web|site-last|папка|api|last|файл.json] [--cache=папка] [--aids=…] [--limit=N]` (`site-last` и папка —
сохранённые страницы сайта, без сети; `--cache` — сквозной кэш ответов: что есть — не качается); `--write --source=папка|site-last|файл.json`
(запись по сохранённым данным — проверка; ничего не скрывает); `--seed-map [--force]`; `--report=N`.

### Jong•Golf по API (запасной источник)

Замена загрузчика старого сайта `wa_loader_jonggolf.php` (FinBoss). Источник «API» — «Настройки» → «Откуда загружать: API бренда».
Как старый загрузчик: 4 раза в день весь каталог поставщика, цены и наличие найденных товаров, новые товары с фото, отсутствующие
у поставщика — скрываются (старый удалял). Включается только после переключения домена (ниже). Пока источник — сайт бренда,
к API загрузчик не обращается вовсе (и пробным прогоном «Текущая очередь API»); пробный прогон по сохранённому ответу API — можно.

**Перенос со старого загрузчика** (старый сайт и его загрузчик в это время работают как раньше):
1. `php bin/install.php` — таблицы раздела (`supplier_*`). Связи «код цвета → товар» для перенесённых товаров Jong•Golf
   создаёт `bin/import-webasyst.php` (строка «Jong•Golf: связей …»; отдельно — `php bin/supplier-jonggolf.php --relink`):
   при первом запуске существующие товары обновляются, а не дублируются.
2. Настройки: «Поставщики → Настройки → Перенести настройки» — файл `wa_loader_jonggolf.cfg.php` со старого сервера
   (или `php bin/supplier-jonggolf.php --import-cfg=путь/wa_loader_jonggolf.cfg.php`). Файл только читается как текст, не выполняется.
   Переносятся окно и период запуска, ключ API (хранится в базе, на экране не показывается), «Полное обновление», флаги
   добавления и изменения товаров, пропускаемые бренды, характеристики, размеры и качество фото, срок хранения отчётов.
   **Не переносятся**: логин и пароль старой админки и «восстановление дерева категорий» (не нужны), тип товаров, мета-шаблоны
   «{name}» / «купить {name} в Одессе» (на новом сайте title/description новых товаров строят SEO-шаблоны раздела «SEO»).
3. Таблица категорий: вкладка «Категории» → `table/category_table_jonggolf.xls` старого загрузчика (формат тот же: A — сезон,
   B — подкатегория, C — пол, D — размерный ряд или пусто, E — путь категории сайта «ДЕТСКАЯ ОБУВЬ>Кеды>12-26»; можно XLSX или CSV;
   или `--import-map=путь`). Путь, которого нет на сайте, подсвечивается — выберите категорию в таблице. Несопоставленные
   сочетания из последнего прогона показаны там же с кнопкой «Добавить». Коэффициенты цен по категориям — вкладка «Цены»
   (у старого наценки не было).
4. Справочники для пробного прогона без связи с API — `tmp/product_setting.json` старого загрузчика («Справочники поставщика»).
5. Поставщик пускает только IP из белого списка: сообщите Jong•Golf внешний IP нового хостинга (с другого IP ответ
   «Access denied for this IP.»). Проверка — «Проверить подключение» (только справочники, у поставщика ничего не меняется).
6. «Пробный прогон» ничего не пишет в каталог и не подтверждает поставщику — показывает, что будет добавлено, изменено,
   скрыто и почему пропущено. Без подтверждения поставщик отдаёт только первую страницу очереди (до 300 товаров).

**Переключение автозагрузки** (строго по порядку: очередь товаров у поставщика общая на ключ, два загрузчика «крадут»
друг у друга обновления):
1. На старом сервере удалите задание cron `wa_loader_jonggolf.php` и дождитесь конца текущего запуска (окна 01, 06, 11, 16 ч).
2. На новом сайте в `config/config.php` — `'debug' => false`: в режиме разработки полная выгрузка (clean_export)
   и подтверждения (callback) не отправляются никогда.
3. «Поставщики → Настройки» — «Откуда загружать: API бренда», «Автозагрузка включена» → «Сохранить». Первый запуск — «Запустить сейчас»
   (или по расписанию), проверьте отчёт («Журнал»). Если скрыть пришлось бы больше половины товаров поставщика — скрытие отменяется само.
   clean_export и подтверждения уходят только при источнике «API» (при источнике «сайт бренда» — никогда).

**Cron**: хватает общего `bin/cron.php` раз в час (раздел 3) — он запускает автозагрузку в окне часов не чаще периода
и продолжает прерванный запуск (старый загрузчик: с 1 до 16 ч, раз в 5 ч; решение владельца для брендов — 0–23 ч, раз в 5 ч).
Время — Europe/Kiev (`app/bootstrap.php`); сверьте «сейчас на сервере» на вкладке «Настройки» с часами, чтобы окна не сдвинулись.
Командная строка: `--test` (проверка связи), `--dry-run --source=api|last|файл.json [--dict=product_setting.json] [--limit=N]`,
`--now` (боевой запуск вне расписания из источника настроек), `--report=N` (отчёт). Отчёты хранятся N дней (настройка, у владельца — 5).
За загрузкой следит вкладка **«Обзор»** (открывается первой, такая же у «Хит обуви» — описание ниже).

## Автозагрузка «Хит обуви» (страницы сайта поставщика)

«Каталог → Поставщики → Хит обуви» (только администратор). У поставщика (hit-obuvi.com.ua, Joomla + JoomShopping) нет API
и выгрузок — загрузчик читает **страницы списков категорий** его сайта (в них есть всё: название, цена ящика и пары, пар
в ящике, размерный ряд, цвет, материал, фото). Карточки товаров не запрашиваются, описания не берутся; большое фото (`full_…`)
скачивается только для новых товаров. Бережно: один поток, пауза между запросами (≥ 1,5 с, по умолчанию 2 с — общая для админки,
cron и командной строки), User-Agent `TomobuvLoader/1.0 (+https://tomobuv.com.ua)`, robots.txt соблюдается; на 429/5xx — пауза
60 с с удвоением, после 3 ошибок подряд — остановка; на 403 и проверку Cloudflare — сразу остановка «нужна проверка» (защиту
загрузчик не обходит). По умолчанию **выключена**.

**Как включить** (порядок важен):
1. `php bin/install.php` — таблицы и колонки раздела (`supplier_*`, журнал изменений `supplier_changes`; миграция
   `database/migrations/suppliers.sql` повторяется безопасно). Таблица категорий заполняется черновиком сама при первом открытии.
2. **Наценка** — вкладка «Настройки» → «Наценка». Цены на сайте поставщика — **закупочные**: пока коэффициент не задан, включить
   загрузку и нажать «Запустить сейчас» нельзя. Цена на сайте за пару = цена поставщика за пару (цена ящика ÷ пар в ящике)
   × коэффициент + надбавка, затем округление (до 1/5/10 грн, по правилам или всегда вверх); старая цена (скидка) — так же;
   ящик и минимальный заказ — «пар в упаковке» поставщика. Закупочная цена сохраняется в карточке товара. Решение владельца
   (октябрь 2026) — у всех поставщиков ×1 (цена на сайте = цене поставщика): в локальных настройках `hitobuvi.markup_k = 1`.
3. Вкладка «Категории» — таблица «категория поставщика → категория сайта» (черновик по разбору сайта поставщика; красные строки —
   без категории сайта, их товары пропускаются), «по рядам» — детские 12-26 / 26-32 / 32-38 / 36-41 по размерам товара,
   правила «тип из названия» (шлепки из «Летней обуви» — в шлепанцы). Одежда, сумки, перчатки — «не загружать».
4. Остальные настройки: какие разделы обходить (по умолчанию 4 обувных), порог id новых товаров (по умолчанию 1 550 000 —
   примерно с апреля 2026: поставщик не снимает архив с 2016 г.), не больше новых за запуск (300), скрывать пропавшие
   у поставщика после N полных проходов подряд (2), «брать под загрузчик» товары Forsage и заведённые вручную (по умолчанию нет —
   только строка «есть на сайте» в отчёте, дубль не создаётся), пропускаемые бренды (по умолчанию Jong•Golf и Tom.m во всех
   написаниях — JONG GOLF, J&G, TOM.M, ТОМ.М… — их ведут свои загрузчики с сайтов брендов; проверяются бренд в названии
   и «Производитель»). Товары сайта, уже связанные с другим поставщиком (Tom.m, Jong•Golf), «Хит обуви» не берёт никогда.
5. «Обзор» → «Проверить связь» (robots.txt и одна страница), затем «Пробный прогон» (быстрый — первые страницы разделов; ничего
   не пишет в каталог): в отчёте — что добавится (с ценами до и после наценки), что найдено на сайте, что и почему пропущено.
6. «Настройки» → «Автозагрузка по расписанию включена» → «Сохранить». Первый запуск можно сделать сразу — «Запустить сейчас».

**Расписание**: по умолчанию сверка каждые 5 ч круглые сутки (окно 0–23, период 5 ч); cron хостинга вызывает `bin/cron.php`
раз в час (раздел 3), он решает, пора ли. Полный проход (цены и наличие всех товаров, ≈1 100 запросов при 100 товарах
на странице, 1,5–2 ч) — не чаще раза в «полный проход, ч» (по умолчанию 24) и только ночью, в часы «полный проход — с … по …»
(по умолчанию 0–6: при периоде 5 ч время запуска сдвигается на час в сутки, 00 → 01 → … → 06; последний запуск в окне — полный уже
через 19 ч (24 − 5), поэтому полный проход есть каждую ночь; запоздавший больше чем на сутки идёт и вне окна); остальные — быстрые
(только новые товары сверху списков, ≈10–20 запросов). Итого около 1 200 запросов в сутки к сайту поставщика. Долгий проход cron ведёт кусками по 40 мин и продолжает в следующий час.
Отдельная строка cron не нужна; если хочется (например, в 15 минут каждого часа):
```
15 * * * *  php /home/USER/tomobuv/bin/supplier-hitobuvi.php >> /home/USER/tomobuv/storage/logs/hitobuvi-cron.log 2>&1
```
Два запуска одного поставщика одновременно не идут (блокировка), пауза между запросами — общая.

**«Обзор»** (общая вкладка всех поставщиков, у Jong•Golf такая же): что сейчас идёт (этап, раздел и страница N из M, счётчики —
обновляются сами раз в 4 с), «Запустить сейчас» / «Остановить» (они же в шапке страницы поставщика), товары поставщика
(связано, на сайте, скрыто, добавлено за последний запуск / 7 / 30 дней, не сопоставлено и пропущено — со ссылками на списки
и отчёт), сверка наличия (пропали у поставщика и скрыты; нет у поставщика, но ещё на сайте — ждут N проходов; вернулись),
изменения цен «было → стало» (у поставщика и на сайте, %, фильтры «подорожали / подешевели», период), последние запуски
(длительность, проверено, добавлено, цен изменено, скрыто, вернулось, ошибки, запросов к сайту поставщика). История цен
товара — блок «Цена у поставщика: история» в его карточке в админке; там же, в «Истории изменений», — все реальные изменения
загрузчика «было → стало» (цена, наличие, видимость, а также ряд, ящик, старая и закупочная цена, категория, фото, «взят под
загрузчик»). Журнал пишут только боевые запуски и только реальные изменения (дата изменения товара сдвигается тоже только
ими); хранится «Историю цен и наличия, дней» (365).
- «Запустить сейчас» работает и при выключенной автозагрузке (ручной запуск), но только с наценкой; пока идёт запуск — кнопка
  неактивна. Шаги делает открытая страница (каждый — до 12 с); закрыли страницу — запуск продолжит cron (через 15 мин без движения).
  Запуск по расписанию после выключения автозагрузки cron не продолжает (статус «Остановлен») — к сайту поставщика не ходит.
- «Остановить»: порция, которая уже пишется, дописывается целиком, запуск получает статус «Остановлен». Остановленный,
  прерванный ошибкой, ограниченный лимитом или быстрый проход, а также проход, где раздел поставщика не открылся (404) или
  пришёл пустым, **никогда не скрывает** товары — только полный проход по всем страницам.
  Защита: если скрыть пришлось бы больше половины активных товаров поставщика — скрытие отменяется.

Командная строка (`bin/supplier-hitobuvi.php`): без параметров — как cron; `--test`; `--now [--mode=quick|full] [--limit=N]`;
`--load [--max-new=N] [--max-requests=N]` (первая загрузка после пересборки каталога — раздел «Пересборка каталога»);
`--dry-run [--source=web|last|папка] [--mode=quick|full] [--limit=N] [--ids=…]` (`last` и папка — сохранённые страницы, без сети);
`--write --source=папка|last` (запись по сохранённым страницам — проверка); `--seed-map [--force]` (таблица категорий из черновика
`database/suppliers/hitobuvi.php`); `--report=N`.

На всех фото поставщика — его водяной знак «hit-obuvi.com.ua»; часть названий у поставщика с чужими брендами (Adidas при
производителе Anda) — проверяйте пробный прогон и при необходимости добавляйте бренды в «Пропускаемые».

## Автозагрузка Tom.m (официальный сайт бренда tomm.ua)

«Каталог → Поставщики → Tom.m (tomm.ua)» (только администратор). Магазин — дилер бренда: данные и фото с сайта бренда брать
можно. API и фидов у бренда нет — загрузчик читает **список поиска** сайта (`/ru/search/?query=&page=N`, по 100 товаров на странице):
весь каталог (≈1 700 товаров) — **17 запросов**, в нём есть код, раздел, цена пары и ящика, старая цена, пар в ящике, ряд, наличие,
фото. Карточка товара (линейка, сезон, материалы) и фото скачиваются только для новых товаров (и фото — для найденных без фото).
Бережно — как «Хит обуви»: один поток, пауза ≥ 1,5 с (по умолчанию 2 с), User-Agent `TomobuvLoader/1.0 (+https://tomobuv.com.ua)`,
robots.txt (у бренда закрыты только кабинет и оформление заказа), 429/5xx — пауза с удвоением, 403 / проверка браузера /
блок-страница сетевого фильтра — сразу остановка «нужна проверка». По умолчанию **выключена**.

**Как включить:**
1. `php bin/install.php` (таблицы `supplier_*` — общие с другими поставщиками). Таблица разделов («Категории») заполняется
   черновиком сама при первом открытии (`php bin/supplier-tomm.php --seed-map`): 16 разделов бренда → «ДЕТСКАЯ ОБУВЬ > …»,
   детские ряды 12-26 / 26-32 / 32-38 / 36-41 — по «Размер» товара.
2. **Наценка** — «Настройки» → «Наценка» (цены бренда — закупочные: без коэффициента загрузку нельзя ни включить, ни запустить).
3. «Обзор» → «Проверить связь» (2 запроса), затем «Пробный прогон» (полный, 17 запросов, ничего не пишет в каталог): в отчёте —
   найденные у нас товары (по связи, по коду, по коду без приставки Forsage), цены до и после наценки, что станет «нет в наличии»,
   что добавится, что неоднозначно. На копии базы октября 2026: найдено 1 118 из 1 587 наших Tom.m, новых у бренда — 539
   (в наличии с ценой — 257), неоднозначных — 8, «похожих» — 17 (код уже есть у товара сайта без бренда, у Tom.m с другим рядом
   или у другого бренда с тем же рядом — новый не создаётся, чтобы не было дубля: проверить вручную, из них в наличии 9), без пары
   у бренда — 469 (список «Есть у нас, нет у поставщика» на «Обзоре»).
4. «Настройки» → «Автозагрузка по расписанию включена» → «Сохранить». Первый запуск можно сразу — «Запустить сейчас».

**Что делает запуск:** найденные товары (Forsage, заведённые вручную) по умолчанию берутся под загрузчик — название, адрес и SEO
не меняются; обновляются цена (× наценка), старая и закупочная цена, ящик, ряд, наличие. «Нет в наличии» у бренда — у нас
«нет в наличии» (товар не скрывается, цена прежняя); пропал с сайта бренда — скрывается только после 2 полных проходов подряд
(остановленный, прерванный, быстрый или неполный проход ничего не скрывает; больше половины активных — отмена). Категорию
загрузчик по умолчанию не меняет (часть наших детских Tom.m лежит в МУЖСКОЙ/ЖЕНСКОЙ — переложить их решает владелец: «Менять
категорию по таблице разделов» + пробный прогон). Новые — только в наличии, с ценой и фото: «Категория Tom.m Код» (RU и UA),
артикул — код бренда, все фото товара (970 px → холст 700×700), характеристики из карточки по-русски (материал «текстиль+кожзам»
→ существующее «искусственная кожа-текстиль»), SEO — шаблоны сайта, не больше 500 за запуск. Нет в наличии у бренда — новый
не создаётся. После перевода найденных товаров на Tom.m импорт прайса Forsage их по forsage-коду больше не найдёт
(`supplier_code` — код бренда): Tom.m в прайсах Forsage — пропускать.

**Загрузка с нуля** (каталог собирается заново из поставщиков): ≈1 150 товаров бренда в наличии; на каждый новый — карточка
и фото (2–3 запроса с паузой 2 с, ≈7 с), порции по 40 товаров. Запуск берёт не больше 500 новых и 1 500 запросов (≈45 мин:
cron ведёт его кусками по 40 мин, продолжает в следующий час) — весь бренд за 3 запуска; быстрее — `php bin/supplier-tomm.php --now`
подряд или «Не больше новых за запуск» больше. Наценка (решение владельца, октябрь 2026) — ×1: цена на сайте = цене бренда
(в локальных настройках `tomm.markup_k = 1`; в коде по умолчанию наценка не задана — без неё загрузка не включается).

на каждый новый товар — обычно 5–10 в сутки; итого ≈90–100). Проход идёт около минуты (17 страниц по ≈2,7 с; сверка 1 700 товаров
с базой — 1–2 с). Отдельная строка cron не нужна (хватает `bin/cron.php`),
если хочется:
```
20 * * * *  php /home/USER/tomobuv/bin/supplier-tomm.php >> /home/USER/tomobuv/storage/logs/tomm-cron.log 2>&1
```
Если бренд против 100 товаров на странице (в меню сайта 24 / 36 / 48) — «Товаров на странице списка» → 48 (36 запросов на проход).

Командная строка (`bin/supplier-tomm.php`): без параметров — как cron; `--test`; `--now [--mode=quick|full] [--limit=N]`;
`--dry-run [--source=web|last|папка] [--mode=quick|full] [--limit=N] [--ids=…]` (папка — сохранённые страницы, например кэш разбора;
без сети); `--write --source=папка|last` (запись по сохранённым страницам — проверка; никогда не скрывает); `--seed-map [--force]`;
`--report=N`. «Обзор» — общий (как у «Хит обуви»), плюс списки «Нет в наличии у поставщика» и «Есть у нас, нет у поставщика».

## Cloudflare и другие прокси перед сайтом

Если сайт открывается через Cloudflare (или перед Apache стоит nginx хостинга), PHP видит адрес прокси, а не посетителя:
все посетители выглядят одним IP, и лимиты попыток входа, отправки форм и заказов становятся общими на всех,
а в журналах и заказах — IP прокси. Чтобы брать настоящий IP из `X-Forwarded-For` / `CF-Connecting-IP`,
перечислите адреса прокси в `config/config.php`:

```php
// все подсети IPv4 и IPv6 со страницы https://www.cloudflare.com/ips/ (список на 28.09.2026; изредка меняется — сверяйте)
'trusted_proxies' => [
    '173.245.48.0/20', '103.21.244.0/22', '103.22.200.0/22', '103.31.4.0/22', '141.101.64.0/18', '108.162.192.0/18',
    '190.93.240.0/20', '188.114.96.0/20', '197.234.240.0/22', '198.41.128.0/17', '162.158.0.0/15', '104.16.0.0/13',
    '104.24.0.0/14', '172.64.0.0/13', '131.0.72.0/22',
    '2400:cb00::/32', '2606:4700::/32', '2803:f800::/32', '2405:b500::/32', '2405:8100::/32', '2a06:98c0::/29', '2c0f:f248::/32',
    // '127.0.0.1',   // если перед Apache ещё и nginx хостинга
],
```
Заголовки принимаются **только** от этих адресов — без списка их игнорируем (подделать их может кто угодно).
Если прокси нет — оставьте `trusted_proxies` пустым. Проверка: «Состояние системы» → «IP посетителей»
(там же видно, если запрос пришёл через прокси, а список не задан). HTTPS за прокси определяется по `X-Forwarded-Proto`
(Cloudflare ставит его сам); режим SSL в Cloudflare — «Full (strict)», не «Flexible».

- [ ] Повторный `php bin/import-webasyst.php` **затирает** каталог, страницы, блог, баннеры, отзывы, заказы и основные настройки магазина
      (раздел 5) — правки в новой админке делайте только после финального переноса.
- [ ] После каждого обновления кода: `php bin/install.php` — применит новые файлы `database/migrations/*.sql` (колонки, индексы;
      повторный запуск безопасен, в конце — «Готово: N SQL-команд», без строки «Ошибок»), затем `php bin/cache-clear.php`. Без этого новые функции падают
      с ошибкой «Unknown column».
- [ ] «Состояние системы»: нет строк «нужно исправить»; строки «Закрыт адрес …» — 403/404 (служебные папки не отдаются).
- [ ] «Сотрудники»: свой администратор создан (`php bin/create-admin.php`), лишние перенесённые учётки отключены или стали менеджерами.

## Скорость

- Кэш готовых страниц включён по умолчанию (`cache.pages`). После правок в админке кэш сбрасывается автоматически;
  вручную — кнопка «Очистить кэш» в админке или `php bin/cache-clear.php`.
- Индекс каталога перестраивается автоматически после изменений; полностью — `php bin/reindex.php`. После обновления, которое
  добавило `database/migrations/catalog-index-sig.sql`, выполните `php bin/reindex.php` один раз: до этого точечная переиндексация
  (сохранение товара, импорт) верная, но медленнее — пересчитывает фильтры категорий товара целиком.
- Включите в панели хостинга OPcache (обычно включён) и PHP 8.2+.
