# Tomobuv — архитектура и правила разработки

Оптовый интернет-магазин обуви на **чистом PHP 8.1+** без фреймворков и Composer.
Рассчитан на обычный хостинг (cPanel/ISPmanager, Apache + MySQL/MariaDB) и каталог 100 000+ товаров.

## Структура


## Почему быстро

1. **Кэш готовых страниц** (`Core/PageCache`). Страницы витрины одинаковы для всех посетителей: всё личное
   (корзина, избранное, сравнение, валюта, «Кабинет») рисует JS из cookie. Страница из кэша отдаётся за 1–3 мс
   ещё до подключения к БД. Контроллер включает кэш: `return Response::html($html)->cache(3600);`
   Сброс — `Cache::flush()` (меняет номер версии; старые файлы удаляет `bin/cron.php`).
   **Нельзя** кэшировать страницы с персональными данными: корзина, оформление, кабинет, админка, POST.
2. **Индекс каталога** `catalog_index` (категория → товары с учётом подкатегорий и динамических категорий)
   с покрывающими индексами под каждую сортировку. Список категории = один проход по индексу + `Products::cards($ids)`.
   Порядок «по убыванию, при равных — id по возрастанию» (как на старом сайте) идёт через вычисляемую колонку
   `product_rid = 4294967295 − product_id` (`… DESC, product_rid DESC`): MySQL/MariaDB не читают по индексу смешанные
   направления сортировки (database/migrations/perf.sql). Новый ORDER BY для витрины — сначала EXPLAIN: без «Using filesort».
   После изменения товаров: `$s = CatalogIndexer::snapshot($ids)` до изменения и `CatalogIndexer::products($ids, $s)` после
   (1–10 товаров — ~20 мс; без снимка тоже верно, ~0,15 с), после массового импорта — `CatalogIndexer::rebuildAll()`
   (полные перестройки — по одной за раз: `CatalogIndexer::exclusive`, блокировка `storage/cache/reindex.lock`).
   Перестройка всего индекса и категории — одна транзакция: витрина до COMMIT видит прежний полный индекс. Всё, что пишет
   в индекс, — под блокировкой записи индекса `CatalogIndexer::locked()` (GET_LOCK), взятой **до** своей транзакции
   (так делает импорт); иначе правка во время перестройки может быть посчитана дважды или потеряна.
3. **Фильтры**: `product_features (feature_id, value_id, product_id)`, заранее посчитанные `category_facets`.
4. **Файловый кэш данных** (`Core/Cache`) для справочников — категории, бренды, настройки, меню.
5. **Сессия только при необходимости** (`Session::start()` вызывается входом, оформлением, админкой).
6. **Фото** — миниатюры создаются один раз при первом обращении, дальше их отдаёт Apache без PHP.
7. Один CSS (≈75 КБ, 15 КБ в gzip), один общий JS, `loading="lazy"`, размеры у картинок, долгий кэш статики в `.htaccess`.
   Шрифт Manrope не блокирует первую отрисовку (preload → stylesheet), до загрузки — «Manrope Fallback» (Arial с подогнанными
   метриками, 00-base.css) — без сдвига вёрстки. Фото первого экрана — без `loading="lazy"` (первая карточка списка — `fetchpriority="high"`).
   Lighthouse (мобильный, Apache c gzip): производительность 95–100, доступность 96–97.

## Правила кода

- **SQL только через плейсхолдеры**: `App::db()->all('… WHERE id = ?', [$id])`, списки — `[$ph, $vals] = $db->in($ids)`.
  Имена колонок/направления сортировки — только из белого списка, никогда из запроса пользователя.
- **Никаких запросов в цикле.** Сначала id, потом пакетная загрузка (`Products::cards($ids)`).
- **SQL — для MySQL 5.7 / 8.0 и MariaDB 10.3+** (на хостинге обычно строгий sql_mode с ONLY_FULL_GROUP_BY):
  псевдонимы-зарезервированные слова MySQL 8 (`empty`, `rank`, `groups`, `row`, `system`…) — в обратных кавычках;
  нет `REGEXP_REPLACE`/оконных функций/CTE в MySQL 5.7 — либо запасной путь в PHP. Новые колонки и индексы в миграциях —
  через проверку `information_schema` (как в `database/migrations/admin-import.sql`); `bin/install.php` повторяет
  миграцию, зависящую от более поздней по алфавиту.
- **Любой вывод в шаблонах — через `e()`**. HTML из базы (описания, страницы) выводится как есть — его пишет админ.
  HTML-поле формы админки сохраняется через `AdminCatalog::staffHtml($html, $изБазы)` (или `PagesController::html($k, $old)`): поле без правок —
  как в базе, изменённое — `HtmlSanitizer::staff()`: администратору — как есть,
  менеджеру — без скриптов, on*-атрибутов, javascript:-ссылок и чужих iframe; описания из импорта — `HtmlSanitizer::supplier()`,
  из файла своей выгрузки (колонки ID и updated_at, `Importer::ownExport`) — `HtmlSanitizer::clean()`, как у менеджера.
- Формы витрины: CSRF «double submit» — `csrf_field()` в форме или заголовок `X-CSRF-Token` (JS: `UI.post()`),
  проверка `Csrf::check()`. Админка: `BaseController` сам проверяет токен сессии на каждом POST (`BaseController::tokenField()`, JS: `Adm.post()`).
- Спам-защита публичных форм: скрытое поле `website` (honeypot) + `RateLimit::hit("key:ip", N, sec)`.
- Цены в шаблонах: `price_html($uah)` (JS пересчитает в выбранную валюту), текстом — `price_format()`.
- Картинки товара: `Image::product($p, '400')`, другие загруженные файлы — `media($path)`.
- Ссылки: категория `Catalog::categoryUrl($c)`, бренд `Catalog::brandUrl($b)`, товар `$p['link']`.
- Ответы: `Response::html()`, `::json()`, `::redirect()`, `::notFound()`. AJAX-ответы: `{"ok":true,…}` / `{"ok":false,"error":"…"}`.
- Стили раздела — отдельный файл `public/assets/css/src/NN-раздел.css` + `php bin/build-assets.php`. Базовый 00-base.css не трогать без необходимости.
- Комментарии — по-русски, по делу.

## Админка — в стиле админки ARG FLEX

Макет `app/Views/layouts/admin.php`: тёмное меню с группами (Обзор / Каталог / Контент / Настройки) и счётчиками,
шапка с заголовком (`$title`), кнопками раздела (`$actions` — HTML) и «Открыть сайт / Выйти», `$back = ['/admin/orders/', 'Все заказы']`.
Стили `public/assets/admin/admin.css`. Компоненты (используйте их, а не свои):

- показатели: `<div class="stats"><a class="stat hot" href="…"><span>642</span>Новых заказов</a>…</div>`
- карточка с заголовком: `<div class="card"><div class="card-hd"><h2>…</h2><a href="…">Все</a></div><div class="pad">…</div></div>`; простая — `<div class="card">…</div>`
- таблица: `<div class="table-scroll"><table class="grid">…</table></div>` (внутри карточки) или `<div class="tblwrap"><table class="tbl">` отдельно;
  строки: `tr.unread` (новое), `tr.is-draft` (скрыто), колонки `.right`, `.tick` (чекбокс), `.thumb`; мелкий текст под значением — `<small>`
- фильтры списка: `<div class="tabs"><a class="on" href="?status=new">Новые <i>12</i></a>…</div>` (таблетки со счётчиком),
  строка поиска/селектов — `.filter-bar` (или `.toolbar`), массовые действия — `.bulk-bar` в начале карточки
- вкладки настроек/форм — `.subtabs`; чипы-фильтры — `.chip(.on)`; статусы — `.st st-new|processing|paid|shipped|completed|refunded|deleted` или `.pill`
- формы: `<label class="fld"><span>Название</span><input …></label>`, сетки `.pair`/`.row2`, `.triple`/`.row3`, чекбокс `.check`,
  подсказка `.hint`, группа SEO — `<fieldset class="seo-set"><legend>SEO</legend>…`, липкая панель сохранения — `<div class="savebar"><button class="btn btn-p">Сохранить</button><span class="hint">…</span></div>`
- кнопки: `.btn` (контурная), `.btn-p` (оранжевая основная), `.btn-d` (удаление), `.btn-sm`; две колонки редактора — `.two-col` (+ `<aside>` справа)
- детали: `<dl class="detail"><div><dt>Телефон</dt><dd>…</dd></div></dl>`, история — `<ul class="events"><li><b>…</b><span>дата</span><em>текст</em></li>`
- пусто: `<div class="empty-card"><h2>…</h2><p>…</p><a class="btn btn-p">…</a></div>`; превью Google — `.serp > .serp-url/.serp-title/.serp-desc`;
  точки SEO — `.seo-dot ok|warn|auto|none`; медиа-сетка — `.media-grid > figure`; график — `.bars > .bar` или SVG `.chart`
- колонки «Title»/«Description» в списках (товары, статьи, страницы, категории): `SeoAudit::listCells($type, $rows)` — пакетно, та же логика,
  что SEO-обзор и витрина; ячейки — партиал `admin/partials/seo-cells`, чипы `?seo=notitle|nodesc|len` — `seo-filter`
  (SQL — `SeoAudit::listWhere()`, в PHP — `listMatches()`; пусто и длина в SQL — по `SeoAudit::sqlTrim()`, как `trim()` в PHP:
  TRIM() в SQL снимает только пробелы), легенда со ссылкой на обзор — `seo-legend`
- сообщения: `$this->flash('Сохранено')` → зелёная плашка, `$this->flash('…', true)` → красная.
- картинки для контента: `public/uploads/ГГГГ/ММ/` через `App\Services\Media::store($file)`; выбор картинки на любом экране — `<button type="button" class="btn" data-media-pick="#поле" data-media-preview="#превью">Выбрать из медиатеки</button>` + `'scripts' => ['admin/media.js']` (для textarea вставляет `<img>` в позицию курсора; из JS — `MediaPicker.open({onSelect(file){…}})`).
- редакторы (товар, категория, бренд, характеристика, страница, статья, баннер) — один вид: над формой переключатель «RU | UA» со счётчиком
  заполненных полей UA — `$view->partial('admin/partials/lang-bar', ['lang' => $lang, 'what' => 'страницы'])` внутри области `[data-lang="ru"]`,
  поля языка — `.l-ru` / `.l-uk`, поля UA — с атрибутом `data-uk`; в каталоге поле в двух языках — `AdminCatalog::i18nField()`,
  SEO-поля с одинаковыми подписями — `AdminCatalog::seoField('meta_title', 'meta_title', $row, […])`, метка языка — `AdminCatalog::langTag('uk')`.
  HTML-поле — `<textarea data-editor>`: один редактор `admin/content.js` (режимы «Визуально | HTML», «Медиатека» вставляет `<img>`,
  вставка из буфера чистится); экраны без content.js подключают его партиалом `admin/partials/editor`. Стили — в конце admin.css.

## SEO — адреса и мета-теги как на старом сайте (Webasyst)

| Страница | Адрес | Title / Description |
|---|---|---|
| Главная | `/` | настройки `seo.home_page_meta_*` |
| Категория | `/category/{url}/`, `?page=N` | свои meta_* категории, иначе шаблоны `seo.category_meta_*` |
| Пагинация | `?page=N` | как основная форма на старом сайте: title и description страницы 1 + « \| Страница N» (один раз — `Seo::pageSuffix`; шаблоны `seo.category_pagination_*` выключены), canonical → первая страница |
| Товар | `/product/{url}/` | свои meta_*, иначе `seo.product_meta_*`; H1 = `seo.product_h1` («{name} оптом в Украине»); keywords — по корневому разделу (`{$category.root_name}`) |
| Бренд | `/brand/{urlencode(name)}/` (`/brand/Mona+Lisa/`) | свои brands.title / meta_description, иначе шаблоны `seo.brand_meta_*` (если `seo.brand_is_enabled`), иначе имя бренда |
| Инфо-страница | `/o-kompanii/` и т.п., а также `/pages/o-kompanii/` | pages.title, иначе `seo.page_meta_title`; description — свой, иначе отрывок текста (`Seo::excerpt`), иначе `seo.page_meta_description`; у дубля `/pages/x/` canonical → `/x/` (`PageController::mainPath`), если свой не задан |
| Блог | `/blog/`, `/blog/{url}/` | список — `blog.meta_title` / `blog.meta_description`; статья — meta_title, иначе «Tomobuv » Заголовок», description — свой, иначе отрывок текста |
| Отзывы, HTML-карта | `/reviews/`, `/sitemap/` | `seo.reviews_meta_*`, `seo.sitemap_meta_*`; пусто — «Отзывы» / «Карта сайта — Tomobuv» без описания |
| Поиск | `/search/?query=…` | «{запрос} — {site_title}», noindex |

`App\Core\Seo::pick($own, 'seo.product_meta_title', $vars)` — своё значение (как есть), иначе шаблон; на /ua/ — «<ключ>.uk» и колонки *_uk.
Переменные шаблонов — одни для витрины, SEO-обзора, превью админки и автоисправления: `App\Services\SeoVars`
(`product.name/seo_name/sku/price/format_price/box_qty/sizes`, `category.name/seo_name/full_name/root_name/product_count`, `brand.name/product_count`,
`page.name`, `store_info.name/phone`). `category.full_name` — «Детская обувь: кеды 26-32» (корень в регистре предложения, у размерной
подкатегории — ближайший предок со словом; на /ua/ — name_uk); подкатегория со словом «обувь»/«взуття» — без повтора: «Детская зимняя обувь 12-26»,
«Дитяче зимове взуття»; одинаковое имя у двух категорий сайта — у вложенной родитель в скобках: «Детская обувь: чехлы-бахилы (весна-осень)».
`category.root_name` — корневой раздел («Женская обувь»; корень не про обувь — «Обувь»). `product.sizes` — только «чистый» диапазон вида 36-41,
`format_price` пуст при цене ≤ 0.
Sitemap: `/sitemap.xml` → `sitemap-shop-N.xml` (по 10 000 адресов), `sitemap-blog.xml`, `sitemap-site.xml`.
Смена адреса в админке (url товара, категории, бренда, страницы, статьи; пустой url — из названия) при отмеченном по умолчанию
«301-редирект со старого» — `AdminCatalog::addRedirect` (страницы и статьи — через `RedirectsController::put` с проверкой пары):
таблица `redirects` без цепочек (A→B, потом B→C даёт A→C и B→C) и петель (редирект с нового адреса удаляется); путь хранится
без /ua — `ErrorController` ищет его после снятия префикса, `Response::send` добавляет /ua к Location (/ua/старый → /ua/новый).
Тот же сервис: импорт прайсов и своей выгрузки с колонкой «Адрес» (смена url найденного товара — 301 всегда, пачкой
`AdminCatalog::addRedirects`), объединение значений «Бренд» (страницы брендов-источников → 301 на оставшийся бренд).
Удаление товара, категории, бренда, инфо-страницы, статьи — `AdminCatalog::dropRedirectsTo`: редиректы, ведущие на удалённый
адрес (в любом написании to_url: «/x/», «/x», %XX, с /ua, ?параметрами, #якорем), удаляются — иначе вели бы на 404.

### Норма и движок шаблонов

Норма — как в SEO-обзоре и точках админки: **title 30–70, description 70–170 символов** (`Seo::TITLE_MIN…DESC_MAX`, `SeoAudit::TITLE_MIN…`)
по тому, что выводит витрина (своё значение или результат шаблона); страницы пагинации не считаются. `SeoAudit::state()`: своего нет —
«По шаблону», но результат шаблона вне нормы — «Длина».
`Seo::build($tpl, $vars, 'title'|'description')` (его вызывает `pick`, поле — по ключу настройки):
- `[[…]]` — необязательная часть: пропадает, если в ней пустая переменная («» или «0»); текст длиннее нормы — такие части убираются
  справа налево (последней пишется наименее важная). В шаблоне с `[[` пустая переменная обязательной части (нет названия) — результата нет;
- `{$x|plural:пара,пары,пар}` — «8 пар» (UA — «пара,пари,пар»), прочие модификаторы старых шаблонов игнорируются;
- схлопываются пробелы и пробелы перед знаками препинания, края без « — | , ; :» (регуляркой /u — `trim()` с «—» режет UTF-8);
- всё ещё длиннее — `Seo::fit`: title по слову без «…» (без висячих знаков, предлогов и союзов; `Seo::cutTail` снимает незакрытую
  скобку с хвостом — «УЦЕНКА(брак: отклеиваются цепочки» → «УЦЕНКА», число без отрезанной единицы — «…бронзовый 4» от «4 пары:…»
  (единица — целым словом, граница по буквам Unicode: «партия», «штиблеты» — не «пар», «шт»; `php tools/seo-test.php`),
  оборванный перечень «4пари:23»), description — по концу предложения, если остаётся ≥ 70, иначе по слову + «…».
  Старые шаблоны Webasyst (`{$product.name} купить…`) работают как раньше.
`Seo::excerpt($html)` — description из текста страницы/статьи: первые связные абзацы (от 8 слов, не «…:», не перечень через запятую),
без скрытых блоков микроразметки (display:none) и заголовков, 120–160 символов по предложению, иначе по слову + «…».

Стандартные шаблоны (RU / UA — `App\Services\SeoFix::TEMPLATES`, тексты служебных страниц — `SeoFix::SERVICE`):
- товар: `{$product.name} оптом[[ — купить в Одессе]][[ | {$store_info.name}]]`; description — название, цена за пару, пар в ящике,
  «купить в Одессе на 7 км или с доставкой по Украине», размеры, магазин;
- категория: `{$category.full_name} оптом[[ — купить в Одессе]][[ | {$store_info.name}]]`; description — «купить ящиками…», число моделей;
- бренд: `{$brand.name} — обувь оптом[[, купить в Одессе]][[ | {$store_info.name}]]`; description — «Обувь X оптом: N моделей в каталоге…»;
- инфо-страница без своего description и без связного текста (`/stati/`): `{$page.name} — оптовый интернет-магазин обуви {$store_info.name}: …`.

### Автоисправление (`App\Services\SeoFix`, `php bin/seo-autofix.php`, «SEO → Исправить автоматически»)

Одно поле объекта, RU и UA решаются вместе:
- своё значение **в норме не меняется никогда**;
- «машинное» своё (title = название или прежнее название, description «купить … в Одессе» / «купити … в Одесі» — выгрузка Forsage
  в Webasyst) и длинный title — набор ключевых слов вне нормы **очищаются** (NULL) — дальше работает шаблон; но если русское своё остаётся,
  а украинское машинное вне нормы, в *_uk пишется результат украинского шаблона (пустой *_uk показал бы на /ua/ русский текст);
- своё «человеческое» вне нормы **исправляется**: повторы слов подряд, заглавная буква, пробел после точки, «Одесса/Украина» с заглавной;
  строки через перевод строки — отдельные фразы («. »); короткий title — хвост из недостающих частей (« оптом», « — купить в Одессе»,
  « | Tomobuv»), короткий description — фраза из недостающих частей (покупка, Одесса, доставка, магазин: у «Купить оптом резиновую обувь…» —
  только « Доставка по Украине — интернет-магазин Tomobuv.»), длинное — `Seo::fit`; нет перевода — UA по исправленному русскому с украинским хвостом;
- шаблон группы заменяется стандартным, только если он пуст, это шаблон Webasyst (его возвращает перенос — `SeoFix::LEGACY`)
  или по нему в норме < 98% объектов группы; удачный шаблон владельца не трогается. Служебные страницы — если текста нет или он вне нормы.
  Keywords/H1 групп о детской обуви для всех (`SeoFix::WORDING`) — нейтральные с `{$category.root_name}`; шаблоны пагинации категорий
  с номером страницы выключаются (номер дважды с « | Страница N»);
- одинаковый title у разных товаров на сайте (`dedupe`) — у всех, кроме одного (самое короткое название), своё значение с различающей
  частью: конец названия, который убрала обрезка («…бронзовый РОЗПРОДАЖ оптом»), у одинаковых названий (дубли карточек) — «(код N)»;
  title, написанный владельцем (не пустой, не = название и не текст шаблона — `SeoFix::ownTitle`), не меняется и здесь;
- значение, которое записал прошлый пакет и с тех пор не меняли, решается заново от исходного значения владельца (`refix`): новые правила
  исправляют прежний пакет без отката (журнал — цепочка «было → стало» по пакетам).

Каждое применение — **пакет**: `seo_fix_batches` + `seo_fix_log` (объект, id, поле, язык, правило, было, стало, время;
database/migrations/seo-autofix.sql). `--revert=N` / кнопка «Откатить» возвращает «было» только там, где сейчас всё ещё «стало» —
значения, изменённые после пакета, пропускаются и перечисляются. Пакеты откатываются от последнего к первому: если более поздний
неоткаченный пакет менял те же поля (объект + колонка, `SeoFix::laterOverlaps`), откат отклоняется — «сначала откатите №…» (в админке
кнопка неактивна с подсказкой, `--list` пишет «откат после №…»); флага «всё равно» нет — иначе «было» позднего пакета (правка раннего)
считалось бы значением владельца, а его откат вернул бы уже откаченное. Повторный запуск ничего не меняет (пустой пакет не сохраняется).
Товары — пачками по 5000 id в транзакции (`SELECT … FOR UPDATE`, решение в PHP, `UPDATE … IN` / `CASE`), без REGEXP_REPLACE;
~15 с проверка и применение на 107 тыс. товаров (сначала без блокировок — title всех товаров для поиска одинаковых). Предпросмотр в админке (только администратор) — итоги «в норме сейчас → после»
по группам и языкам, шаблоны, 50 примеров, что останется не в норме; «Применить» считает заново на свежих данных.
Перенос не откатывает тексты: последний шаг `bin/import-webasyst.php` и `bin/i18n-seed-uk.php` — тот же SeoFix (отдельный шаг — своя часть,
«seo» — только он); украинские шаблоны в `database/i18n/uk/settings.php` и `migrations/product.sql` — стандартные.
Перенос исправляет раньше сида, когда перевода ещё нет: *_uk, которые он заполнил русским текстом (uk_fill, dedupe-копия русского
«Ботинки … (код N)») и которые с тех пор не меняли (`SeoFix::autoFilledUk`), сид считает пустыми и заменяет переводом из словаря.
Сид не пишет в *_uk «машинные» title/description (= название, «купити … в Одесі», набор ключевых слов) вне нормы при пустом русском
своём (`SeoFix::seedSkipsUk` — та же проверка, что очистка в автоисправлении): цикл «сид → автоисправление» даёт 0 изменений.
Название товара без русских слов (Угги, Дутики, Балетки… — одинаковые в обоих языках, раздел в конце `database/i18n/uk/product_words.php`;
бренды, коды, украинские слова поставщика) сид пишет в пустой name_uk и совпадающим с русским; незнакомые слова печатает.
Новые товары, категории, статьи без своих мета получают результат шаблона в норме сами; своё значение вне нормы, сохранённое в админке,
не правится — только точка и подсказка в превью Google (`admin/partials/serp`).

## Автоназвание товара

Обычное название — «Тип Бренд Артикул» («Кроссовки Baas L1873-1»). Товар, заведённый одним кодом («60189A», «B31127-3»,
«68188С» с кириллической С — в названии нет слова из 3+ кириллических букв), получает название «{Категория} {Бренд} {Код}»:
«Зимняя обувь Tom.m 60189A», на /ua/ — «Зимове взуття Tom.m 60189A» (name_uk категории и бренда). Категория — основная; без слова
в имени («32-38») — ближайший предок со словом; нет категории — без неё; нет бренда или «Не указано» — без бренда.
UA-название заполняется, только если пустое или тоже код; пустой артикул получает код («Артикул: 60189A»). Адрес (url) не меняется.
Всё — в `App\Services\ProductName` (`isBare`, `build`, `fix`), вызовы: сохранение товара в админке (сообщение «Название дополнено: …»;
у товара, уже названного правилом, снова введённый код пересобирает вместе с русским и UA-название с артикулом, если их не правили — `fix($d, $old)`),
импорт прайсов (новый товар; у найденного — если файл меняет название на код: собранное правилом пересобирается, своё полное
название с тем же кодом остаётся; при ключе «Название» код из файла находит товар по артикулу), перенос с Webasyst (после шага products),
`php bin/product-names.php [--dry-run]` — для уже заведённых. Массовые действия названий не трогают.
`bin/i18n-seed-uk.php` для таких товаров (`ProductName::generated`) берёт UA-название из той же сборки, а не из словаря.

## Даты и история товара (`App\Services\ProductHistory`)

Список товаров — колонка «Загружен» (`products.created_at`, у перенесённых — дата на старом сайте; под ней время и источник),
сортировка «Дата загрузки» (индекс `products.created`). Карточка — блок «Даты»: «Загружен · источник», «Изменён · кем/чем» (только
реальные изменения после загрузки, иначе «изменений не было»), последние 10 событий, «Вся история» — `/admin/products/{id}/history/`.
Миграция — database/migrations/product-history.sql (`ProductHistory::ensureSchema()` выполняет её сама).
- Источник — `products.source`: `webasyst` (bin/import-webasyst.php), `import` (новый товар импорта), `manual` (форма админки);
  загрузчики source не пишут — источник по `products.supplier` из `Suppliers::LIST` (Jong•Golf, «Хит обуви», Tom.m). Уже заведённые
  товары миграция разметила один раз по журналам (product_create, import_seen.created, supplier_changes new / связь, созданная
  вместе с товаром), остальное — перенос. `settings.webasyst.products_at` — когда перенесены товары: правки до этого — «на старом
  сайте», записи журналов о том же id до переноса не показываются.
- История — из журналов, которые уже есть (на товар — по запросу на журнал, по индексам): `admin_log` (индекс `entity`):
  product_update с `details.ch` — «было → стало» у цены, наличия, названия, категории, статуса, бренда…, тексты и SEO — «изменено»;
  фото (upload / delete / sort); по записи на товар без user_id (кто — `details.by`) — `product_bulk` (массовые действия),
  `product_import` (импорт: создан, `ch` из плана строки, скрыт «нет в файле»; import_seen хранит только флаг и 30 дней),
  `product_autoname` (ProductName::scan) — это `ProductHistory::QUIET`, их нет в «Безопасность → Действия сотрудников»
  (там общая запись действия); `supplier_changes` (загрузчики: добавлен, цена поставщика и наша, скрыт, нет в наличии, вернулся,
  `edit` — остальные реальные изменения «было → стало»: взят под загрузчик, старая/закупочная цена, ряд, ящик, категория, фото…);
  `seo_fix_log` (автоисправление SEO, по пакетам). Запись — `ProductHistory::log()` пачкой, `describe()` / `line()` — формат изменений.
- `updated_at` сдвигается только реальным изменением: форма товара пишет только отличающееся (`ProductHistory::changed` после
  `AdminCatalog::keepUnchanged`; категории и характеристики — множествами; адрес, который не меняли, — прежним написанием;
  бренд и размер, не показанные формой — ссылка на удалённое значение, — прежние), «Сохранить» без правок — «Изменений нет»;
  массовые действия — только товары не в нужном состоянии; фото — загрузка, удаление, смена порядка; импорт — только изменённые
  строки и первое фото найденного товара; загрузчики — по своему сравнению полей. Автоисправление SEO updated_at не сдвигает
  (машинные title/description у 100 тыс. товаров — не правка данных; иначе импорт своей выгрузки после него считал бы изменёнными все
  товары), в истории оно есть. Своя выгрузка → правка → импорт: изменённый после выгрузки товар не перезаписывается, сохранённый без правок — не «изменён».

## Автозагрузка поставщиков (каркас, Jong•Golf, «Хит обуви», Tom.m)

Общий каркас — `app/Services/Suppliers`, админка «Каталог → Поставщики» (`/admin/suppliers/` — список, `/admin/suppliers/{код}/` —
страница поставщика; только администратор), установка и включение — docs/INSTALL.md.
- `Supplier` (абстрактный, методы вызываются на классе адаптера — `static::`): настройки `settings` «{код}.*» (`cfg`, `on`, `lines`),
  расписание (окно часов + период: `due`, `nextRun`; `cron` — продолжить прерванный запуск или начать новый), запуски `supplier_runs`
  (`createRun` под блокировкой запусков поставщика `withLock` — GET_LOCK, общий для админки, cron и CLI; `step` — шаг в бюджете
  времени → `advance` адаптера; `stop` — условный UPDATE «Остановлен»; итог `finishRun` только поверх «Идёт»; «зависший» — `STALE`),
  отчёт `supplier_run_log` (пачкой: `log` → `flushLog`), уборка (`cleanup`: отчёты «{код}.log_days», журнал изменений
  «{код}.history_days», связи с удалёнными товарами). `enabled()` — включено и выполнены условия адаптера; `manualAllowed()` —
  можно ли «Запустить сейчас» (по умолчанию = `enabled()`).
- `SupplierSync` — общая запись порции: одна транзакция под `CatalogIndexer::locked` (взятой до транзакции) с повтором при
  взаимной блокировке (`transact` → `apply` наследника), бренды и значения характеристик без дублей (`brandRef`, `valueIds`),
  пакетный UPDATE по белому списку `UPDATABLE`, адреса новых товаров, фото через GD в холст (`frame`, `storePhoto` →
  `Image::originalPath`), встреченные коды запуска `supplier_run_seen`, журнал изменений (`journal`, `journalHidden`):
  каждое реальное изменение записи — строкой журнала (цена — `price`, видимость — `hidden`/`back`, наличие — `out`/`back`,
  остальное — `edit` с «было → стало» из `ProductHistory::describe/line`, `editNote`); `updated_at` — только у изменённых.
- Загрузчики со страниц сайта поставщика (Хит обуви, Tom.m, Jong•Golf с сайта бренда) — ещё два общих слоя:
  `WebSupplier extends Supplier` — наценка (`markup`, `price`: цена поставщика — закупочная, без коэффициента нельзя ни включить,
  ни «Запустить сейчас»), режим по расписанию (`autoMode`: полный — не чаще `full_hours` и в окне `full_from–full_to`, иначе быстрый),
  общие поля формы (`checkCommon`), ошибки сайта (`onSiteError`: retry — пауза 60 с с удвоением, 3 подряд — ошибка; limit — проход
  неполный), «Проверка связи» (`testRun`), `lastWeb`, `linkCounts`, `foundText`; `SiteClient` — бережный HTTP-клиент (только GET,
  один поток, пауза ≥ 1,5 с общая для всех процессов — GET_LOCK по хосту + `storage/import/{код}/last-request`, UA `TomobuvLoader/1.0`,
  robots.txt на сутки, лимит запросов; 429/5xx → `retry`, 403 / Cloudflare / блок-страница сетевого фильтра → `blocked` без обхода;
  режим без сети — папка ответов, сквозной кэш; cookie списка входит в ключ ответа «адрес#cookie=…»; второй хост того же
  поставщика — `HOSTS` (фото Jong•Golf на public.jonggolf.com: свой robots.txt, пауза и блокировка общие); `obtainable` — ответ
  сохранён или robots.txt разрешает (без сети robots.txt не запрашивается — сохранённая копия или «правил нет»)), ошибки — `SupplierError`
  (kind, http); `WebSync extends SupplierSync` — цикл порций (`process` → `portion`: сеть — до транзакции и в бюджете шага, первый
  товар с сетью — всегда; `enrich` — карточки, `netCost`), все фото товара (`photos` → главное + `more`, `storePhotos`; фото, закрытое
  robots.txt, не запрашивается — ошибка фото этого товара, а не останов запуска), `seen` (и пропущенные), `report`, `diff` (только
  отличающиеся поля), `finish` — скрытие после N полных проходов с защитой 50 %; пропавшие, которых ещё рано скрывать, — `missingStock`
  наследника (Jong•Golf: «нет в наличии»). Наследник задаёт `items()` (разбор + поиск + решение), `apply()` и `data()`.
- «Один товар — один поставщик»: товар, связанный (`supplier_links`) с одним поставщиком, другие не находят и не меняют
  (`SupplierSync::foreignLinked`); значения характеристик от поставщиков — по-русски (`SupplierSync::ruValue`, словарь
  `database/suppliers/uk-values.php`: «чорний» → «черный», «штучна шкіра» → «искусственная кожа»).
- `Suppliers` — реестр «код → класс»; `bin/cron.php` обходит всех (каждый — в своём try). `SupplierOverview` + `admin/suppliers/overview`
  + трейт `SupplierPages` (контроллеры) — вкладка «Обзор» одна на всех: сводка по `supplier_links` (связано, на сайте, скрыто,
  `missed` — нет в последних полных проходах), журнал `supplier_changes` (new / price — цена поставщика `old_cost→new_cost`
  и наша `old_price→new_price` / hidden / out — «нет в наличии» у поставщика / back / edit; пишут только боевые запуски и только реальные
  изменения; код товара для людей — `Supplier::codeLabel` (Tom.m: артикул из `ext_id` вместо id бренда)), последние запуски, ход запуска (GET …/progress/ — опрос раз в 4 с, шаги — POST …/runs/{id}/step/, suppliers.js), кнопки
  «Запустить сейчас» / «Остановить» в шапке (`headerActions`). Адаптер с `TRACKS_STOCK` (наличие переносится на сайт без скрытия) —
  список «Нет в наличии у поставщика»; с `ownBrandIds()` (сайт одного бренда) — «Есть у нас, нет у поставщика» (товары бренда без связи).
  У загрузчиков со страниц сайта трейт даёт и действия: настройки, проверка связи, старт, отчёт запуска, шаг, остановка
  (у Jong•Golf — свои: метод контроллера важнее метода трейта); партиалы `admin/suppliers/markup` и `web-runs`.
  Блок «Цена у поставщика: история» в карточке товара — `admin/suppliers/price-history`.
- Таблицы: `supplier_links (supplier, code → product_id, ext_id, hidden, missed, seen_at, cost)`, `supplier_runs`,
  `supplier_run_log`, `supplier_run_seen`, `supplier_category_map` (kind: '' — сочетание Jong•Golf, 'cat' — категория поставщика,
  'type' — тип из названия; mode, by_size), `supplier_changes` — database/migrations/suppliers.sql (колонки — через information_schema).

**Как добавить поставщика**: класс `X extends Supplier` (со страниц сайта — `extends WebSupplier`, клиент `XClient extends SiteClient`
с BASE/SUPPLIER/ERROR, порции `extends WebSync`) (CODE, TITLE, DEFAULTS, `enabled`, `start` → `createRun`, `advance` — фазы
со состоянием в `$run['state']`, продолжение после обрыва; при необходимости `manualAllowed`, `phaseLabel`, `percent`, `skipReasons`,
`CHECKS_MISSING` / `COUNTS_REQUESTS` / `TRACKS_STOCK` / `ownBrandIds` для «Обзора»), `XSync extends SupplierSync` (`SUPPLIER`, `apply`; в `$items` — `id`, `code`,
`action` create|update|same|hide, `ex` — строка товара до записи, `upd`, `cost`/`old_cost`, `returned`, `hide_note` — для журнала),
строка в `Suppliers::LIST` и `ABOUT`, контроллер с `use SupplierPages` (`sup()`, `supBase()`, вкладка «Обзор» — `overviewData()`
+ партиал `admin/suppliers/overview`), маршруты в `app/routes/admin_suppliers.php`, CLI `bin/supplier-x.php`, раздел в INSTALL.md.
Записываемый товар — `products.supplier = код`, `supplier_code` и связь `supplier_links`; скрывать пропавших — только после
полного прохода, с защитой «больше 50 % активных — отмена»; неполный/остановленный запуск ничего не скрывает.

### Jong•Golf (официальный сайт бренда www.jonggolf.com — основной источник)

`JongGolf extends WebSupplier` — один поставщик `jonggolf` с двумя источниками (настройка `jonggolf.source`: `site` — по умолчанию,
`api` — запасной, ниже); связи `supplier_links` (code — код цвета «B40678-3», ext_id и `products.supplier_code` — id модели = id_product API),
таблица категорий и «Обзор» общие — источник переключается без перепривязки. `liveSrc()` (web | api) — src боевого запуска,
`lastStart` расписания — по обоим. Сайт бренда: `JongGolfClient extends SiteClient` (BASE www.jonggolf.com, HOSTS public.jonggolf.com —
фото; адреса `/api/` этим клиентом не запрашиваются), `JongGolfParser` (список и карточка модели), `JongGolfSiteSync extends WebSync`
(порции по 40), общее с API — трейт `JongGolfShared` (поиск товаров, названия, SEO, сравнение характеристик, фильтр категории).
- Список — весь каталог в наличии одним запросом `/ru/catalog/?limit=1000` (≈2,2 МБ, по сети ≈110 КБ, ≈2 с): блок «one-product-list»,
  data-* (id модели, слаг, код цвета, цена пары, пар в ящике, ряд), «Сезон | Категория | Бренд», пол, старая цена, метки. Цвет без остатка
  бренд не показывает. Полнота — сумма фасетов пола формы фильтра = числу цветов; меньше — запасной путь `?limit=100&page=N`; не
  похоже на список (нет блоков и нет «товаров не найдено») — ошибка `layout`: в каталог ничего не пишется, товары не скрываются.
  Каждый проход полный (быстрого режима нет). Фазы: start (проверки, разделы из черновика, robots.txt списка и фото → `state.photos_ok`)
  → list (`runs/N/list-1.html`, после обрыва не качается; `items.json`) → items → finish.
- Поиск (как у API): связь → название старого загрузчика «{категория API по-украински} {бренд} {код}» → код цвета в артикуле и конце
  названия у товаров без поставщика (кириллица = латиница); связанный с другим поставщиком — не находится. Найденный («adopt_manual»,
  по умолчанию да; название, адрес, SEO не меняются): цена пары цвета (у цветов одной модели — своя) × наценка, старая цена (скидка
  бренда), закупочная — цена бренда, ящик, ряд, в наличии, скрытый загрузчиком — снова показан; категория — `update_category`;
  характеристики — `update_features`, только поля списка; фото — только товару без фото.
- Новый — только в наличии (других бренд не показывает), с ценой, категорией, рядом, ящиком и фото; не больше `max_new` (500) за запуск:
  `ProductName::build` («Зимняя обувь Jong•Golf B40678-3» / «Зимове взуття …»), артикул — код цвета, бренд — из списка («Jong•Golf™»
  и «Не указано» — настройка «Бренд»), карточка модели `/ru/{слаг}.html` (1 запрос на модель, `runs/N/card-*.json`): материалы,
  повторные размеры, описание (только RU), доп. фото цвета; по карточке цвета уже нет / «снята с продажи» — не создаётся. Значения
  характеристик — по-русски (`ruValue`), существующие — без учёта регистра и пробелов; название цвета — из справочника API
  (`storage/import/jonggolf/product_setting.json`), на сайте бренда только код.
- **Фото и robots.txt**: фото — `public.jonggolf.com/files/products/{модель}/{фото}/b_….jpg` (800×705), но robots.txt этого хоста (как у www)
  содержит «Disallow: */product*» — по RFC 9309 это закрывает и /files/products/. Такие фото не запрашиваются (`obtainable`): новый цвет
  без фото — пропуск `robots_photo` (с «Добавлять без фото» — создаётся без фото), найденный без фото — без фото, доп. фото из карточки —
  не берутся; в отчёте — строка-предупреждение и `stats.photo_robots`. Разрешит бренд (`User-agent: TomobuvLoader` / `Allow: /files/products/`
  или Allow в группе «*») — заработает само: robots.txt перечитывается раз в сутки, товарам без фото фото добавится следующим проходом.
- Категория (`JongGolfMap::site`): таблица сочетаний старого загрузчика (kind '') по русским названиям сайта, затем по украинским
  (черновик `database/suppliers/jonggolf.php`, uk: «Демисезоная обувь» → «Демисезонe взуття», пол — «та» и «і дівчаток»); не нашлось —
  раздел бренда «сезон|категория» (kind 'cat', черновик sections → «ДЕТСКАЯ ОБУВЬ > …»), по рядам — `JongGolfMap::row` по нижнему размеру
  (≤ 22 → 12-26, 23–28 → 26-32, ≥ 29 → 32-38; буква ряда бренда бывает ошибочной) → `HitObuviMap::child`; «не загружать» — пропуск.
- Нет в полном проходе (`WebSync::finish` → `JongGolfSiteSync::missingStock`): связанный товар — сразу «нет в наличии» (in_stock 0,
  остаток 0, цена прежняя, журнал `out`), после `missing_runs` (2) полных проходов подряд — скрыт (`hidden`); вернулся — показан и
  в наличии (`back`). Проход по сохранённым страницам (кроме пробного), с отбором `aids`, лимитом, остановленный, неполный — ничего не
  меняет у отсутствующих. Защита 50 % — общая.
- Запросов: проход — 1 (+ robots.txt двух хостов раз в сутки); 5 ч круглые сутки → ≈5 проходов, ≈7 запросов в сутки плюс карточки
  и фото новых. Админка — `SuppliersController` (вкладки «Обзор», «Настройки», «Категории»: разделы бренда и таблица сочетаний, «Цены (API)»,
  «Журнал»), CLI — `bin/supplier-jonggolf.php` (`--source=web|site-last|папка|api|last|файл.json`, `--cache`, `--aids`).

### Jong•Golf: API бренда (запасной источник)

Замена `wa_loader_jonggolf.php` старого сайта: `App\Services\Suppliers\JongGolf` — настройки (`settings` «jonggolf.*», по умолчанию выключено),
расписание (окно часов + период, `bin/cron.php`), машина шагов (dict → page → items → confirm → finish, продолжение после обрыва);
`JongGolfSync` — порция товаров; `JongGolfApi` — 3 метода API; `JongGolfMap` — таблица соответствия `supplier_category_map`
(XLS читает `BiffReader`). Админка — `SuppliersController` (`/admin/suppliers/jonggolf/`), CLI — `bin/supplier-jonggolf.php`.
- Товар поставщика (id_product) × цвет (images[].aid) = товар сайта: `products.supplier = 'jonggolf'`, `supplier_code` = id_product
  (общий для цветов), связь `supplier_links (supplier, code → product_id, hidden)`. Поиск: связь → название старого загрузчика
  «{категория поставщика} {бренд} {код}» → код в артикуле и конце названия у товаров без поставщика (заведённые вручную;
  без настройки «брать под загрузчик» не меняются и не дублируются). Кириллические С/А/В… в кодах = латинские.
- `clean_export` и подтверждение страницы (`export_product_callback`) — только боевой клиент (`new JongGolfApi(true)`)
  при источнике «API», включённой загрузке и `debug = false`; проверка — в `JongGolfApi`. Подтверждение — после записи всей страницы.
- «Обновлять характеристики / описание / заменять фото» пишут только отличия (`sameFeatures` — множества значений полей настройки,
  описание — сравнение с текущим, фото — тот же файл после холста = замены нет): повторный проход не сдвигает `updated_at`.
- Ключ API не выводится нигде (в форме — «ключ задан (64 символа)») и не передаётся аргументом в функции, которые могут бросить
  исключение: `JongGolfApi` читает его из настроек в закрытое свойство, запись — `JongGolf::storeKey(['key' => …])`
  (иначе при `zend.exception_ignore_args = Off` первые 15 символов попали бы в трассировку и журнал ошибок); сообщения — через `mask()`.
- Порция (20 товаров) — одна транзакция под `CatalogIndexer::locked` (до транзакции) со снимком и `CatalogIndexer::products`,
  как импорт; в конце запуска `Cache::flush()`. Фото — `Importer::fetchMany` (защита от SSRF), вписывание в холст через GD,
  путь как у Webasyst (`Image::originalPath`); новый товар без скачанного фото не создаётся. Идёт полная перестройка индекса
  (блокировка занята) — порция откладывается до скачивания фото; фото скачиваются до ожидания блокировки (не дольше остатка
  бюджета шага) и лежат в папке запуска (`photo-*.jpg`) — отложенная порция их не качает снова; шаг заканчивается с `wait`
  (админка и CLI повторяют через 5 с).
- «Остановить» — условный `UPDATE … AND status = 'running'` (под блокировкой запусков, если она свободна); шаг проверяет статус
  перед каждой порцией, подтверждением страницы и скрытием, а свой итог («Готово», «Ошибка») пишет тоже только поверх «Идёт».
- Бренды и значения характеристик из API раскодируются до конца (`JongGolf::name`: «J&amp;amp;amp;G» → «J&G»), в названиях
  товаров — «J&G». Бренд сайта: с раскодированным названием «J&G», иначе по названию как в базе от ответа поставщика
  с раскодированием по уровню («J&amp;amp;G», id 72267, со старого сайта — находится, не переименовывается и не дублируется),
  иначе по раскодированному названию (из нескольких — с большим числом товаров).
- «Полное обновление» скрывает (а не удаляет) товары, которых нет в выгрузке, с защитой «больше 50 % активных — отмена»;
  скрытые загрузчиком (`supplier_links.hidden`) показываются снова, когда цвет вернулся.
- Новые товары: название — `ProductName::build` («Категория Бренд Код», RU и UA) или как старый загрузчик (настройка),
  адрес — `JongGolf::translit` (1-в-1 со старым), SEO — шаблоны сайта, если в настройках пусто.

### «Хит обуви» (страницы сайта поставщика)

`HitObuvi extends WebSupplier` (адаптер, «hitobuvi.*»), `HitObuviClient extends SiteClient` (только GET, один поток, пауза ≥ 1,5 с общая для всех процессов —
GET_LOCK + метка `storage/import/hitobuvi/last-request`, User-Agent `TomobuvLoader/1.0`, robots.txt на сутки, лимит запросов
на запуск; 429/5xx → `HitObuviError('retry')` (наследник `SupplierError`) — пауза 60 с с удвоением, 3 подряд — ошибка; 403 и Cloudflare-проверка →
`blocked` — сразу ошибка, без обхода; режим без сети — папка сохранённых ответов), `HitObuviParser` (список JoomShopping:
`productitem_{ID}`, цены ящика и пары, короткое описание RU/UA, меню, производители, forsage-код из «машинного» алиаса),
`HitObuviMap` (таблица `supplier_category_map` kind cat/type, черновик `database/suppliers/hitobuvi.php`, детские ряды
по размерам), `HitObuviSync extends WebSync` (порции по 40), `App\Services\UkWords` (словарь UA-названий — общий с `bin/i18n-seed-uk.php`).
- Фазы: start (проверки) → page (страница раздела `?limit=100&start=N` → `storage/import/hitobuvi/runs/N/page-K.html`, после
  обрыва повторно не качается; на первой — меню: новые категории поставщика — в таблицу без категории сайта) → items → finish.
  full — все страницы 4 разделов; quick — сверху, пока внизу страницы есть товары новее связанных (не больше `quick_pages`).
  Страница без `productitem_` и без признаков пустой категории — останов (сменился шаблон), товары не скрываются.
- Поиск: R1 связь → R2 forsage-код из адреса (товар `supplier = 'forsage'`) → R3 точное название + ряд (без поставщика, forsage,
  hitobuvi; jonggolf, tomm — никогда) → R4 тип + бренд + «хвост» названия (кириллица = латиница) + ряд, только единственный.
  Найденный чужой (Forsage, вручную) без «брать под загрузчик» не меняется и не дублируется (строка «есть на сайте»).
  Бренды со своим загрузчиком с сайта бренда (Tom.m, Jong•Golf — `skip_brands` по умолчанию: JONG GOLF, Jong•Golf, Jong Golf, J&G, J&amp;G, J&amp;amp;G,
  TOM.M, Tom.m, TOMM, ТОМ.М; написания сравниваются по ключу
  `HitObuviSync::bkey`: J&amp;amp;G = J&G, ТОМ.М = TOM.M) пропускаются по бренду из названия и по «Производителю»; товар сайта,
  связанный с другим поставщиком или с брендом из пропускаемых, в R2–R4 не находится (причина `foreign`) — дубль не создаётся.
- Цена за пару = цена ящика ÷ пар × k + надбавка с округлением (`HitObuvi::price`); пар = цена ящика ÷ цена пары; закупочная —
  `purchase_price`, цена поставщика за пару — `supplier_links.cost` (история «Обзора»). Новый товар — только id ≥ порога,
  с сопоставленной категорией, рядом и скачанным фото (`full_` из адреса миниатюры, по одному через клиент → GD 700×700);
  название поставщика (тип по-русски), «голое» — `ProductName`, UA — `UkWords`, бренд — из названия по брендам сайта
  и производителям поставщика (иначе фабрика без страны), характеристики по настройке, SEO — шаблоны сайта.
- Скрытие — только полный проход по всем страницам (раздел с 404 или пустым списком, отбор `ids` — проход неполный; прерванный
  запуск по расписанию cron продолжает, только пока автозагрузка включена): связанные товары, которых не было `missing_runs` (2) полных проходов подряд
  (`supplier_links.missed`), → status 0 и `hidden = 1`; вернувшийся — показывается снова (журнал back).

### Tom.m (официальный сайт бренда tomm.ua)

`Tomm extends WebSupplier` («tomm.*», по умолчанию выключено), `TommClient extends SiteClient` (cookie `products_per_page`,
метка `storage/import/tomm/last-request`), `TommParser` (плитка Webasyst Shop-Script / тема supreme: id `product_id`, код = название,
адрес → раздел, цена пары и ящика, старая цена, «Пар в ящике», «Размер», наличие `div.stock yes|no`, фото `data-images` 970 px;
карточка: H1 и артикул, линейка «Бренд», сезон, материалы, фото — только из папки этого товара `/products/NN/NN/{id}/images/`:
на карточке есть плитки «похожих» со своими фото), `TommMap` (таблица `supplier_category_map` kind cat:
раздел бренда из адреса → категория сайта, по рядам — `HitObuviMap::row/sizeChild`; черновик `database/suppliers/tomm.php`),
`TommSync extends WebSync` (порции по 40), админка `TommController` (`/admin/suppliers/tomm/`), CLI `bin/supplier-tomm.php`.
- Список — поиск с пустым запросом `/ru/search/?query=&page=N` с cookie `products_per_page=100`: весь каталог (≈1 700 товаров)
  за 17 запросов, новые сверху. Фазы: start → list (`runs/N/page-K.html`; страница без плиток или не с тем числом плиток —
  ошибка `layout`: в каталог ничего не пишется, товары не скрываются) → match → items → finish. Полный проход — все страницы;
  быстрый (только ручной) — сверху, пока на странице есть несвязанные товары. Расписание по умолчанию (решение владельца):
  окно 0–23, период 5 ч, `full_hours` 5, окно полного 0–23 — каждый запуск полный, ≈82 запроса в сутки (4,8 прохода × 17).
  Запуск с отбором `ids` или лимитом — не полный (не скрывает и для расписания не «полная сверка»).
- Сопоставление — сразу для всего каталога (`TommSync::plan`, фаза match → `runs/N/items.json`), правила по очереди для всех:
  R1 связь (`supplier_links`: code = id товара у бренда, ext_id = код; сменился код у того же id — `recode`, товар не меняется),
  R2 точный код (`TommSync::norm`: кириллица = латиница, без «-», « LED», хвоста Forsage « 1») + ряд (единственный — и при другом
  ряде, с предупреждением), R3 код без 1–2-буквенной приставки Forsage + ряд, только единственный. Код у нас — `ourCode`: артикул
  (если не ряд), иначе после «TOM.M», иначе последнее слово с цифрой. Только товары брендов «tomm.brands», кроме товаров других
  загрузчиков и связанных с другим поставщиком. Неоднозначные — пропуск (не меняются, новый не создаётся).
- Найденный (`adopt` по умолчанию да): `supplier = 'tomm'`, `supplier_code` = код; цена = пара × k + надбавка (округление),
  старая — так же, закупочная — цена бренда; ящик, мин. заказ, ряд; артикул-ряд Forsage — новый ряд, пустой — код. Нет в наличии
  у бренда (там цена 0) — `in_stock = 0`, `stock = 0`, цена прежняя, журнал `out`; вернулся в наличие — `back`. Название, адрес,
  SEO не меняются; категория — только с `update_category` (по умолчанию нет); фото — только товару без фото.
- Новый — только в наличии, с ценой, сопоставленным разделом, рядом и фото: название `ProductName::build` («Категория Tom.m Код»,
  RU/UA), артикул — код, бренд — первый из «tomm.brands», характеристики по настройке (карточка: материалы и т. п. — `ruValue`,
  «кожзам» → «искусственная кожа»; составной «текстиль+кожзам» — как уже есть на сайте через «-» в любом порядке, `TommSync::combo`),
  все фото → GD 700×700, SEO — шаблоны сайта; не больше `max_new` (500) за запуск и `max_requests` (1 500) запросов — загрузка
  бренда с нуля (≈1 150 в наличии) за 3 запуска. Пропал с сайта бренда — скрыть после 2 полных проходов (`WebSync::finish`).

## Опт

Цена в базе — за пару (`products.price`), в ящике `box_qty` пар. Корзина и заказ считаются **в ящиках**,
в `order_items.quantity` хранятся **пары** (как в Webasyst). Доставка бесплатна от `settings.free_shipping_boxes` ящиков (20).

## Локальная разработка

```
php bin/install.php                         # таблицы
php bin/import-webasyst.php                 # перенос со старой базы (config webasyst_db)
php bin/i18n-seed-uk.php                    # украинские переводы → колонки *_uk
php -S localhost:8080 -t public public/router.php
node tools/check.mjs http://localhost:8080/ --shots=shots   # ошибки JS/PHP, мобильная вёрстка, скриншоты
```
Проверка без кэша страниц: cookie `nocache=1` (например, `curl -b "nocache=1" …`). Сброс кэша: `php bin/cache-clear.php`.
